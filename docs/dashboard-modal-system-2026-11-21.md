# Shared dashboard modals — 2026-11-21

The seven dashboard dialogs now use `Frontend/Scripts/DashboardModal.html`, included after DashboardPage within the existing dashboard-enabled branch. This is a presentation-only native-dialog component: it moves each instance's existing heading, description, content and footer action nodes into one common header/body/footer shell. IDs, listeners, current fields and business handlers are retained. It mounts idempotently and needs no new library, API, backend or sheet schema.

Updated instances: Inventory summary, Delivery summary, Return summary, Sales summary, Units sold summary, Transactions summary, and Date range. All summary dialogs use a 680px maximum width; the date picker uses the component's 420px compact variant. Phone dialogs use the same 16px padding and viewport-safe height. Shared border, radius, shadow, overlay, typography, control and focus styling reuse the application's tokens. The close button is created once by the component and appears at the top right in every instance. The date picker gains a proper title, description and close button while retaining month navigation, presets, drag/keyboard selection and Apply/Cancel.

The body owns scrolling, including Return which previously scrolled its entire dialog. Headers and action footers stay accessible, with sticky table headings/totals preserved. Footer secondary/navigation actions are on the left and the existing primary download or Apply action on the right. Transactions gains a secondary Close action. Existing primary, secondary, disabled and loading controls use consistent app styling; report loading remains an icon spinner with no Preparing message. All seven are read-only summaries or a date selection; there are no destructive actions requiring confirmation. Shared danger styling is available, and actual report failures use alert semantics and a consistent danger callout without changing their text or retry behavior.

Native modality retains background inertness and focus restoration. The shared component provides an accessible close label and initial focus, explicit forward/reverse Tab wrapping, safe Escape, entry animation and animated close requests with reduced-motion support. It observes existing download aria-busy state; close and secondary actions are disabled and click/Escape/submit dismissal is blocked until the request finishes. Native programmatic close remains available for logout/session cleanup. No global modal code was changed; existing RetailUI still manages app scroll locking and other dialogs.
